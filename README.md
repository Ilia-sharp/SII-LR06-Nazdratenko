# SII-LR06-Nazdratenko · Рекомендательные ИИ-системы · Вариант 16

**Лабораторная работа «Рекомендательные ИИ-системы»**
Дисциплина: Системы искусственного интеллекта. Автор: **Nazdratenko**.

> Репозиторий сохранил имя `SII-LR06-Nazdratenko` от предыдущей лабораторной
> работы. Содержимое заменено полностью: здесь больше нет генерации
> изображений — только рекомендательный сервис на событийных данных
> Retailrocket.

Сервис по `visitorid` (или по списку `itemid` текущей сессии) возвращает
**Top-10 товаров** с оценками. Реализованы и сравнены две модели:

1. **популярностный baseline** — сумма весов событий по товару;
2. **item-item / co-visitation** — совместные появления товаров в сессиях.

Модель обучается только на train-части, тест отделён по времени. Из выдачи
исключаются товары, уже встречавшиеся в истории пользователя.

## Индивидуальный вариант

| Параметр | Значение |
|---|---|
| Номер варианта | **16** |
| Условие | `visitorid % 30 = 15` |
| Сценарий | **Один источник истории** |
| Индивидуальное условие | **Использовать только последние события пользователя** |
| Выдача | **Top-10** |
| Целевые события теста | `addtocart` + `transaction` |
| `view` | только контекст, не цель |

«Один источник истории» реализован буквально: контекст рекомендаций — это
только последние события **самого пользователя** (последние 5 событий,
дубликаты товаров схлопываются). Сессии других посетителей не подмешиваются
в контекст; они используются только при обучении co-visitation.

Учебные веса основного эксперимента (не официальные веса Retailrocket):

| `transaction` | 5 | сильный сигнал, цель |

## Методика

### 1. Временное разделение

Последние **20% временного диапазона** — test, остальное — train. Граница
считается по времени, без случайного перемешивания:

```
cutoff = max(timestamp) − 0.2 × (max(timestamp) − min(timestamp))
```

| Часть | Строк | Доля строк | Границы |
|---|---:|---:|---|
| train | 2 266 031 | 82.23% | 2015-05-03 — 2015-08-21 12:35:39 UTC |
| test | 489 610 | 17.77% | 2015-08-21 12:36:21 — 2015-09-18 UTC |

Доля строк в test ниже 20%, потому что трафик в последние недели выше.
Главное — test **позже** train по времени и не пересекается с ним.

### 2. Сессии

Сессия — события одного `visitorid`, между соседними событиями не более
**30 минут**. Новый посетитель всегда начинает новую сессию. На train
получилось 1 436 517 сессий (в среднем 1.577 события, максимум 417).

### 3. Популярностный baseline

На train для каждого `itemid` суммируются веса событий:

```
score(item) = 1 × views + 3 × addtocarts + 5 × transactions
```

Сортировка: по убыванию score, при равенстве — по возрастанию `itemid`.
Из выдачи удаляются товары из истории пользователя.

### 4. Item-item / co-visitation

На train для каждой сессии берутся уникальные товары в хронологическом
порядке; каждая пара внутри сессии увеличивает совместную частоту на 1.
Матрица симметричная: `co_visit(a, b) = co_visit(b, a)`.

Ограничение реализации: в очень длинных сессиях учитываются последние
**50 уникальных товаров** (защита от квадратичного роста; затрагивает доли
процента сессий). Итог: 215 683 товара в словаре, 2 004 561 вхождение пар,
1 724 569 уникальных пар, в среднем 15.99 соседа на товар.

Скор кандидата для пользователя:

```
score(c) = Σ weight(context_item) × co_visit(context_item, c)
```

где `weight` — вес события контекста (1/3/5). Кандидаты из истории
пользователя исключаются, остаются Top-10.

### 5. Контекст варианта 16

Для пользователя берутся **последние 5 событий**, затем дубликаты товаров
схлопываются (остаётся самое свежее событие). Порядок — от свежего к
старому, вес — вес этого события. Используется только история данного
`visitorid`; это и есть «один источник истории».

### 6. Оценка

Для каждого целевого пользователя (`visitorid % 30 = 15`) собираются
уникальные товары из `addtocart` и `transaction` в test. Контекст и история
берутся **строго до первого целевого события test**: модель обучалась
только на train, а более ранние события test могут быть контекстом, потому
что они уже произошли к моменту выдачи. Сами целевые события в контекст не
попадают.

Метрики считаются на одних и тех же «тёплых» пользователях для обеих
моделей (у пользователя есть контекст и хотя бы одна цель):

```
Precision@10 = |Top-10 ∩ Target| / 10
Recall@10    = |Top-10 ∩ Target| / |Target|
NDCG@10      = DCG@10 / IDCG@10,  релевантность бинарная
```

## Результаты

Тестовая группа варианта: 9 311 посетителей, из них **226** совершили
`addtocart`/`transaction`; 48 — холодный старт (до первого целевого события
нет событий), 178 участвуют в оценке. Средняя длина контекста — 1.79 товара.

| Модель | Precision@10 | Recall@10 | NDCG@10 | HitRate@10 |
|---|---:|---:|---:|---:|
| Popularity baseline | 0.000562 | 0.000268 | 0.001236 | 0.005618 |
| **Item-item / co-visitation** | **0.006180** | **0.021191** | **0.015219** | **0.056180** |

Co-visitation лучше baseline примерно в 11 раз по Precision@10 и в 12 раз
по NDCG@10. Абсолютные значения низкие из-за разреженности Retailrocket:
235 тыс. товаров, короткие сессии, всего 10 позиций в выдаче.

### Вспомогательный срез: только новые цели

46.8% пар «пользователь–целевой товар» уже были в истории до момента выдачи
(например, просмотр → покупка того же товара). По условию лабораторной
такие товары **нельзя рекомендовать**, поэтому они заведомо не могут попасть
в Top-10. Ниже — метрики только по целям, которых ещё не было в истории
(43 пользователя, 209 пар):

| Модель | Precision@10 | Recall@10 | NDCG@10 | HitRate@10 |
|---|---:|---:|---:|---:|
| Popularity baseline | 0.002326 | 0.001163 | 0.005118 | 0.023256 |
| **Item-item / co-visitation** | **0.025581** | **0.124636** | **0.078371** | **0.232558** |

## Ошибки, ограничения, cold start и утечки

* **Cold start.** 48 из 226 целевых пользователей не имели событий до
  первого целевого события. Они исключены из основной оценки; в API для них
  работает популярностный fallback. Это честнее, чем подставлять им
  co-visitation без контекста.
* **История и повторные покупки.** 46.8% целевых пар уже были в истории.
  Фильтрация истории (требование лабораторной) делает такие попадания
  невозможными; это главная причина низкого Recall. Вспомогательная таблица
  выше показывает качество на принципиально рекомендуемых товарах.
* **Разреженность.** Средняя длина контекста — 1.79 товара, большинство
  сессий состоят из одного события. Co-visitation часто опирается на одну
  пару, поэтому score грубый.
* **Популярность.** Глобальный baseline почти не персонализирован и
  проигрывает co-visitation; после фильтрации истории его верхние товары
  часто выбывают.
* **Ограничения реализации.** Нет категорий и `item_properties` (они не
  обязательны); длинные сессии обрезаются до 50 уникальных товаров; нет
  временного decay (это другой вариант задания); нет онлайн-обновления.
* **Утечки.** Train/test разделены по времени; популярность и пары считаются
  только по train; контекст оценки берётся строго до первого целевого
  события; целевые события test не попадают ни в обучение, ни в контекст.
  `visitorid` — анонимный идентификатор, его величина не используется как
  признак, только остаток по модулю для выбора группы варианта.

Тесты проверяют очистку данных, временное разделение, сессии, веса
популярности, симметричность co-visitation, фильтрацию истории, контекст
последних событий, формулы метрик и интеграцию CLI/API на синтетическом
наборе. GitHub Actions (`.github/workflows/ci.yml`) запускает pytest на
Python 3.12.
